# PTPN 形式化发生规则

> 本文按当前项目语义描述 PTPN（Priority Time Petri Net）的状态类发生规则，以及 `example/common/input-no-period.json` 的前 20 个状态类转移。

---

## 1. 网结构

PTPN 定义为：

\[
N=(P,T,F,W,M_0,\alpha,\beta,\pi,c,s)
\]

| 符号 | 含义 |
|---|---|
| `P` | 库所集合 |
| `T` | 变迁集合 |
| `F \subseteq (P\times T)\cup(T\times P)` | 流关系 |
| `W:F\to\mathbb N^+` | 弧权重；当前任务链示例中通常为 1 |
| `M_0:P\to\mathbb N` | 初始标识 |
| `\alpha:T\to\mathbb N` | 最早发生时间 |
| `\beta:T\to\mathbb N\cup\{\infty\}` | 最迟发生时间 |
| `\pi:T\to\mathbb Z` | 优先级；数值越大，优先级越高 |
| `c:T\to\mathbb Z` | 核心编号；`c(t) >= 0` 表示任务/核心相关变迁，`c(t) < 0` 表示无核心控制变迁 |
| `s:T\to\{0,1\}` | 是否可挂起；`1` 表示该变迁被更高优先级任务抢占时需要冻结已等待/已执行时间 |

---

## 2. 多实例标识与任务链

标识 `M` 是多重集合：`M(p)=n` 表示库所 `p` 中有 `n` 个 token，因此同一任务入口、ready 或 exit 库所可以同时承载多个任务实例。多个实例竞争同一个核心资源库所 `core_k`；若 `M(core_k)=1`，说明核心空闲，某个 `get_core` 变迁可消耗该 token。

每个普通任务节点转换为：

```text
entry -- t_get_core --> ready -- t_exec --> exit -- t_to_next --> next_entry
```

| 片段 | 时间窗口 | 核心 | 语义 |
|---|---:|---:|---|
| `t_get_core` | `[0,0]` | 任务核心 | 消耗 `entry` 和 `core_k`，进入 `ready` |
| `t_exec` | 任务 WCET 区间 | 任务核心 | 从 `ready` 执行到 `exit`，并释放 `core_k` |
| `t_to_next` | `[0,0]` | `-1` | 依赖/控制 token 传递，不占核心 |

抢占/恢复路径由转换器显式加入网中，例如高优先级 B 抢占低优先级 A 时会有 `B_resume_preempt_A_*` 与 `A_resume_B_*` 一类变迁和对应的 suspended 库所。

---

## 3. 状态类

一个状态类写作：

\[
S=(M,C,E,X,R,\Theta)
\]

| 分量 | 含义 |
|---|---|
| `M` | 当前标识 |
| `C(t)=(lb_t,ub_t,st_t)` | 变迁 `t` 的时钟；`st_t ∈ {UNACTIVE, ACTIVE, SUSPENDED}` |
| `E` | 原始使能集合：只由标识决定 |
| `X` | 可调度集合：由 `E` 经过按核心优先级过滤后得到 |
| `R` | 挂起集合：使能但被同核心更高优先级变迁压制的可挂起变迁 |
| `Θ` | 累计时间；它是搜索元数据，不是状态等价的核心语义分量 |

三种时钟状态：

- `UNACTIVE`：变迁未使能或刚发生后被重置，不计时。
- `ACTIVE`：`t ∈ X`，时钟随时间推进。
- `SUSPENDED`：`t ∈ R`，时钟冻结；恢复后继续从冻结值计时，不从 0 开始。

---

## 4. 使能集合 E

变迁 `t` 在标识 `M` 下使能，当且仅当所有前置库所 token 足够：

\[
t\in E(M) \iff \forall p\in{}^\bullet t,\; M(p)\ge W(p,t)
\]

`E` 只表示 Petri 网结构上的可发生候选，还没有应用优先级调度。一个状态中可以有多个使能变迁来自不同核心，或者来自无核心控制路径。

---

## 5. 可调度集合 X：按核心过滤 + 控制变迁保留

`X` 是从 `E` 过滤出的可调度集合，不是全局唯一变迁。它分两类：

1. **同一核心上的任务/核心相关变迁**：每个核心只保留当前使能变迁中优先级最高者。
2. **无核心控制变迁**：`c(t)<0`，不参与核心竞争，若使能则直接保留在 `X` 中。

对每个核心 `k >= 0`：

\[
E_k=\{t\in E\mid c(t)=k\}
\]

若 `E_k` 非空，则：

\[
X_k=\{t\in E_k\mid \pi(t)=\max_{u\in E_k}\pi(u)\}
\]

无核心控制集合：

\[
E_{ctrl}=\{t\in E\mid c(t)<0\}
\]

最终：

\[
X=E_{ctrl}\cup\bigcup_{k\ge0}X_k
\]

因此 `X` 可以包含多个变迁：例如 core0 的最高优先级任务、core1 的最高优先级任务，以及若干控制变迁。**但状态类图中的一条边只发生 `X` 中的一个变迁**；从同一状态发出的多条边是不同的非确定性选择，不表示这些变迁同时发生。

---

## 6. 挂起集合 R

对 `t ∈ E \ X`，若它是可挂起变迁，且同核心上存在更高优先级的可调度变迁，则 `t` 进入挂起集合：

\[
t\in R \iff t\in E\setminus X \land s(t)=1 \land c(t)\ge0 \land \exists a\in X:\; c(a)=c(t)\land\pi(a)>\pi(t)
\]

挂起时：

\[
st_t := SUSPENDED
\]

并保持 `lb_t, ub_t` 不变。直观上，挂起不是取消使能，而是冻结该变迁已经累计的等待/执行时间。

---

## 7. 时间推进

只有 `X` 中的 ACTIVE 变迁推进时钟；`R` 中的 SUSPENDED 变迁冻结。

当前实现使用最大时间推进策略：

\[
\Delta = \min_{t\in X} ub_t
\]

若 `X` 为空，或 `Δ` 不可推进，则没有时间推进。否则：

\[
\forall t\in X:\; lb_t:=lb_t+\Delta,\quad ub_t:=ub_t+\Delta
\]

\[
\forall t\in R:\; C(t)\text{ 保持不变}
\]

---

## 8. 单步发生规则

从状态 `S` 展开后继时：

1. 由 `M` 计算 `E`。
2. 由 `E` 计算 `X` 和 `R`。
3. 只推进 `X` 中 ACTIVE 变迁的时钟。
4. 对 `X` 中每个变迁分别尝试发生，生成多条备选边。

变迁 `t` 可以在状态 `S` 中发生，当且仅当：

\[
t\in X \land st_t=ACTIVE \land \max(\alpha(t),lb_t)\le\beta(t)
\]

发生时间记为：

\[
\tau(t)=\max(\alpha(t),lb_t)
\]

发生效果：

\[
M'=M-{}^\bullet t+t^\bullet
\]

发生后的 `t` 时钟重置为 `UNACTIVE`，然后根据新标识重新计算 `E'`,`X'`,`R'`。

重要约束：

- `SUSPENDED` 变迁不能发生，即使它仍在 `E` 中。
- 不在 `X` 中的变迁不能发生，即使它在 `E` 中。
- 同一状态多条出边是不同的单步选择；每条边只消费/产生一次 token。

### 关键澄清：s2 的两条出边不是同时发生

在 `s2` 中：

- `T5(Aexec)` 的时间窗口是 `[3,8]`，所以边 `s2 -> s4` 的发生时间是 `3.00`。

这两条边都来自同一个状态类的可调度集合 `X`，但它们是两个不同的单步后继选择：

```text
s2 -- T5@3.00 --> s4
s2 -- T6@0.00 --> s5
```

它们不是“同时发生”。状态类图表达的是可达关系的分支：每条边发生一个变迁；若多个变迁都在 `X` 中，则会分别尝试，生成多条备选边。

## 12. 展开算法

```text
expand(S):
  E := { t | enabled(M,t) }

  X := { coreless control transitions in E }
  for each core k:
    add all highest-priority transitions in { t in E | c(t)=k } to X

  R := {}
  for each t in E \ X:
    if suspendable(t) and exists a in X on same core with pi(a) > pi(t):
      R.add(t)
      freeze clock(t)

  advance clocks of ACTIVE transitions in X
  keep clocks of SUSPENDED transitions in R unchanged

  successors := {}
  for each t in X:
    if clock_state(t)==ACTIVE and max(alpha(t), lb_t) <= beta(t):
      successors.add(fire_one_transition(S,t))

  return successors
```

这也是本次修复后代码应满足的核心不变量：`fire_one_transition` 只能接受 `t ∈ X` 且 `clock_state(t)==ACTIVE` 的变迁。
